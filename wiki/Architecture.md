# Native SDK architecture

The product is a C++20 static library, `ash-core.lib`, containing nine APS semantic modules and a separate caller-owned support diagnostics responsibility. SDK product `1.0.0-rc.1` uses architecture-specific x64/ARM64 Release assets; [Conformance and Release Status](Conformance-and-Release-Status) records the adopted authority bindings and mandatory release gates.

`StateModel` validates and assesses states using explicit operational context. `TransitionRegistry` applies canonical codeword transitions. `RecoveryEngine` composes those modules and owns failed-correction, fallback, containment and terminal restrictions. `Diagnostics` validates record identity and ancestry and serializes full diagnostic and typed safety transports. `RealmEncoder`, `TopologyGenerator` and `AxiomEvaluator` produce their corresponding semantic evidence. `GenerationPlanner` builds an inspectable pure plan, and `ArtifactEmitter` returns traceable descriptors; the application owns filesystem materialization.

The explicit seven-field generation request has separate target provenance and optional measured axiom inputs. A complete plan retains normalized/transformed states and realms, every structural topology node/leaf and role, all five explanatory axiom evaluations, artifacts, warnings and registry metadata. `aps-windows-plan-2` binds the complete request/evidence/registry payload and replaces earlier hashes. The emitter checks stored semantic consistency as well as identity before copying all declared descriptor fields; rehashing an inconsistent plan does not authorize output. Legacy state/target defaults remain available, and missing axiom measurements remain `INDETERMINATE`. See [Integration](Integration) for the supported native references and rebuild requirement.

Typed containment/halt projections retain original/action diagnostics and ordered causal ancestry, with local UTC entry/adoption time outside semantic identity. Independent imported histories remain separate and exportable. Semantic objects and mutable diagnostic fields require caller serialization; borrowed model/registry instances must outlive their recovery engine. Owning diagnostic leaves retain parents while roots are observed through weak references. Public record layout changes require consumer rebuilds.

Support `Session` owns a bounded local store and immutable snapshots. Actual rich collection is compiled only into the Debug backend; public Release libraries compile essential Fault/Health collection. Snapshot exports produce paired JSON/Markdown with a completion marker and explicit privacy/error handling. The support concurrency contract does not extend to mutable semantic modules, and caller-instrumented evidence does not promise automatic crash flush or ambient capture.

See [Public API and Boundaries](Public-API-and-Boundaries), [Integration](Integration), [Diagnostics](Diagnostics), [Compatibility](Compatibility) and [Build and Verification](Build-and-Verification). ARM64 cross-build/link evidence does not establish runtime execution; intended OS-floor and physical-device qualification remain owner phases.
