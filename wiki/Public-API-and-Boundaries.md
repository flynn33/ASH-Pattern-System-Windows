# Public API and boundaries

The SDK exposes StateModel, TransitionRegistry, Diagnostics, RecoveryEngine, RealmEncoder, TopologyGenerator, AxiomEvaluator, GenerationPlanner and ArtifactEmitter, together with state/codeword/diagnostic records, generated Version identity and SupportDiagnostics.

Structural normalization preserves all nine coordinates and realm identity. Operational safety assessment requires explicit application context. Fallback candidates come from a declared policy instance with verification evidence; there is no universal domain-safe fallback. Containment restricts mutation and SAFE_HALT is terminal.

`DiagnosticEnvelope` carries meaningful notes, typed JSON details and nullable occurrence metadata, with identity recomputed from the canonical nine semantic fields. `RecoveryEngine` exposes optional typed containment/halt records with the original/action diagnostics, complete ordered chain, typed trigger and local UTC entry/adoption time. `Diagnostics` serializes the corresponding complete safety transports. Prevented attempts retain blocked containment evidence; confirmed breach enters frozen halt. Existing external terminal evidence is locally enforced with `POLICY_HALT_REQUEST`, without fabricating external trigger/time. Invalid imported graphs/actions reject before adoption. Prior independent histories remain available through `retained_diagnostic_chains()` and are exported separately with `serialize_chain()`.

The record layouts changed during this prerelease; consumers must rebuild/relink. Semantic objects remain caller-serialized. Support session concurrency is a separate contract; Debug-only source owns rich evidence collection and Release-only source owns minimal essential capture.

Planning accepts the seven-field `GenerationRequest`: project name, seed state, ordered transitions, topology depth, profile ID, naming policy ID and emission target kind. Separate `GenerationPlanningInputs` carry target provenance and optional measured axiom subject/profile label. The native registry supports `aps-windows-descriptor-1.0`, realm/project naming policies and descriptor output for desktop/mobile/service targets at depths 0 through 6. The legacy state/target overload uses project `ash-plan`, no transitions, depth zero, realm naming and unavailable axiom measurements.

The complete plan retains source/destination realms, every structural node/leaf and role, all five explanatory axiom results, artifact declarations, warnings and registry metadata. Missing measurements stay `INDETERMINATE`; failing evidence stays explicit. Its `aps-windows-plan-2` payload binds all behavior-affecting request/evidence/registry fields with byte lengths, counts, optional presence and exact measurement bits. Earlier hashes require regeneration. SDK product version does not replace the `aps-windows-1.0` provenance label or any native registry identity.

Planning is side-effect-free. The emitter audits complete stored evidence and hash without calling the planner, blocks rehashed inconsistent plans and copies every declared descriptor's ID/kind/name/summary/role references with its plan-element trace. The application owns filesystem materialization; output-directory configuration does not cause SDK file writes. Public plan/artifact record changes require clean rebuilds.

Installed consumers may use only curated headers/library/integration/sample. Producer source, tests, governance, authority corpora, policy tools and repository downloads are outside their dependency graph. The release inventory declares the precise allowed files.
