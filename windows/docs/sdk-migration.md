# Prerelease source and ABI migration

`DiagnosticEnvelope::chain_root_reference` is now `std::weak_ptr<DiagnosticEnvelope>`. Use `auto root = envelope.chain_root_reference.lock()` and handle an expired root explicitly. The builder returns owning roots/leaves, and a child retains its owning parent ancestry. Keeping only a weak root reference does not extend lifetime. Do not replace the fix with a no-op-deleter shared pointer or create an owning self-cycle.

The public record layout also includes explicit diagnostic identity and operational context/fallback data. Existing correct names remain where practical, but binary layouts are not compatible with old packages. Remove old objects/libraries and perform a clean consumer rebuild/relink against one complete versioned SDK. Mixing old headers and new archives is unsupported.

The adopted canonical APS `1.0.0-rc.3` at `50d7e5ab88932a4a967ffc2c83bd18fae45b73c8` requires `schema_version`, meaningful nonempty `notes`, structured `details`, and nullable `occurrence_metadata`. Its SHA256 semantic identity covers exactly `diagnostic_kind`, `disposition`, `rule_ids`, `severity`, `stage`, `subject_reference`, `summary`, `notes` and `details` under canonical compact sorted UTF-8 JSON. IDs use `APS-DIAG-` plus the first 24 uppercase digest characters. Migrating a stored rc.1 record requires its complete explanatory content and separate old provenance; retaining an old digest after changing notes or details is invalid. Windows rule constants now use the canonical `ASH-TRANSITION` and `ASH-DIAGNOSTIC` families. Causal validation uses explicit safety phases for modern and retained legacy stages; operation enum ordinals do not establish escalation order.

Rc.3 preserves the corrected rc.2 semantic diagnostic IDs. Its machine schemas now reject already-invalid blank explanations and multiline summaries, and its explicit normative reconciliation supersedes only the named conflicting older clauses. Rebind canonical schema/corpus, product-version metadata, checksums and provenance together to the new exact commit. Retain original rc.1 evidence and actual rc.2 repair/integration evidence separately.

Contained denial records advance the retained audit tail without changing prior records or the state. A confirmed boundary violation adds breach evidence and enters terminal `SAFE_HALT`; it does not use `FAILED`. Every later rejected engine call returns the original frozen terminal diagnostic. Typed correction/fallback revalidate the supplied assessment against its current context and honor contained, failed and halted runtime restrictions even after a prior correction failure.

Successful fallback replacement accepts the algorithm's `STABLE`, `CORRECTABLE` and `UNSTABLE` post-classes. A non-`STABLE` replacement still requires its declared correction or target-resolution action; fallback resolution alone does not certify a stable operational state.

Use `RecoveryEngine::containment_record()` and `safe_halt_record()` for typed safety projections, then the corresponding `Diagnostics::serialize_transport(record, product_version)` overload. A projection includes original/action diagnostics, the complete ordered chain, typed trigger, system state and action-specific metadata. `containment_time` and `halt_time` are UTC engine entry/adoption times outside semantic identity. Adopting an existing external terminal chain records local `POLICY_HALT_REQUEST` enforcement and local adoption time; it does not reconstruct an unknown external trigger or time. Invalid imported graph/action evidence throws before adoption changes the engine.

When importing a valid independent observer chain, the engine preserves its previous history through `retained_diagnostic_chains()` and exposes the active tail through `diagnostic_chain()`. Export each retained chain separately with `Diagnostics::serialize_chain(leaf)`. Do not concatenate or reparent independent roots into a synthetic causal history. Keep semantic records caller-serialized; owning references extend lifetime but do not make their public fields immutable.

The additive subject-based axiom API takes actual caller measurements and evaluates all five fixed predicates. Compatibility verdict helpers remain available, but their caller-supplied conclusions are not evidence that the subject predicates were evaluated.

Structural normalization preserves the input realm. The default structural classifier is a convenience, not a health judgment about an arbitrary application. Use explicit validated operational context and supplied fallback policy instances for operational assessment. Containment restrictions and terminal halt are enforced at the mutation owner. Failed correction diagnostics remain failures rather than being overwritten by a stable unchanged state.

Do not replace the semantic registry string `aps-windows-1.0` with SDK product `1.0.0-rc.1`; it participates in plan identity. Canonical version, product version, engineering policy, realization-profile catalog, semantic registry, package metadata schema and support-export schema are deliberately distinct. [Authority bindings](sdk-integration.md#authority-bindings) records the adopted policy `0.7.0` and profile catalog `0.7.2`, with the native baseline profile unchanged. Release acceptance must be established by the exact released `qualification.json`, bound to its clean source and asset bytes.

Planning now accepts the exact seven-field `GenerationRequest` plus separate `GenerationPlanningInputs` for target provenance and optional measured axiom evidence. The plan retains complete topology, typed node roles, all five axiom results/explanations and declared descriptor records. Missing measurements remain `INDETERMINATE`; failing measurements remain explicit failures/warnings. The legacy state/target overload delegates with project `ash-plan`, no transitions, depth zero, realm naming, descriptor output and no measured subject.

Plan identity now uses `aps-windows-plan-2`, binding all behavior-affecting request, evidence and registry fields through length-prefixed values, ordered counts, optional presence and exact IEEE-754 measurement bits. Earlier incomplete plan hashes are not preserved: regenerate plans through the current planner and retain old provenance separately. `generation_plan_identity_payload(plan)` exposes the current payload. The emitter rejects inconsistent or incomplete plans even after a caller recomputes their hash, and returns the full declared descriptor fields. Plan/artifact layouts also require a clean rebuild/relink. See [planning and descriptor emission](sdk-integration.md#planning-and-descriptor-emission) for supported native references and request fields.

Upgrade side-by-side, update the SDK property, and rebuild/relink. Repair by verifying hashes and extracting into a fresh SDK folder. Remove references and delete only the old SDK folder after confirming the application no longer uses it. There is no registry registration or installer repair/uninstall operation for this ZIP SDK.
